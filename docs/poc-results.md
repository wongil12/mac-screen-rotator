## 결과

### 기준 상태

- 활성 디스플레이: 1개
- Core Graphics contextual display ID: 1
- 유형: MacBook built-in, main
- 회전: 0°
- 논리 해상도: 1512x982
- 물리 픽셀: 3024x1964
- 주사율: 120Hz
- 스케일링: on

### 회전 시험

90°, 180°, 270°를 각각 3초간 적용한 뒤 0°로 복구했다. 세 시험 모두 `CGDisplayRotation`을 통해 목표 각도 적용과 0° 복구를 확인했다.

각 시험에서는 회전 명령보다 먼저 별도 failsafe 프로세스를 시작했다. 정상 원복 후에도 failsafe가 15초 시점에 원래 모드를 다시 적용했다.

모든 시험 후 다음 값이 기준 상태와 일치했다.

- 회전: 0°
- 논리 해상도: 1512x982
- 물리 픽셀: 3024x1964
- 주사율: 120Hz
- 스케일링: on

### 권한

`displayplacer` 자체 실행에는 관리자 암호, 손쉬운 사용 권한, 화면 기록 권한 요청이 나타나지 않았다. Codex 실행 환경에서는 로그인 세션의 WindowServer 접근을 위해 도구 sandbox 외부 실행 승인이 별도로 필요했으나, 이는 제품 앱에 요구되는 macOS 개인정보 권한과는 다르다.

### 발견한 호환성 이슈

`displayplacer 1.4.0`에서 각도만 전달하면 macOS 26.2 환경에서 미지정 해상도를 `0x0`으로 처리하여 실패했다.

```text
Screen ID 1: could not find res:0x0 scaling:off
```

PoC는 목표 각도에 맞는 해상도, 주사율, 스케일링을 회전 명령에 함께 전달하도록 수정했다. 90°와 270°에서는 논리 해상도의 가로와 세로를 교환한다. 이 방식으로 세 방향 모두 성공했다.

### 판정

**0단계 성공.** Apple M5 MacBook Pro와 macOS 26.2에서 내장 디스플레이 네 방향 전환이 가능하며, 로그아웃이나 재부팅 없이 원래 디스플레이 모드로 복구할 수 있다.

다음 단계에서는 `displayplacer` 실행 파일 의존성을 그대로 제품에 노출하지 않고, 회전 엔진을 격리한 helper 또는 라이선스 고지를 포함한 내장 모듈로 정리한다.
