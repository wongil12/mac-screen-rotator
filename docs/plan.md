# Mac Screen Rotator 개발 계획

## 1. 결론과 기술 제약

MacBook 내장 디스플레이 회전은 기술적으로 가능하다. 목표 각도는 0°, 90°, 180°, 270°다.

다만 macOS의 공개 Core Graphics API는 현재 회전 각도 조회(`CGDisplayRotation`)만 제공하고 회전 설정 API를 공개하지 않는다. 따라서 회전 엔진은 검증된 `displayplacer` 구현을 이용해 하드웨어 호환성을 먼저 확인한 뒤, 제품화 단계에서 다음 중 하나로 결정한다.

1. MIT 라이선스인 `displayplacer` 회전 코드를 고지와 함께 포함한다.
2. 필요한 비공개 MonitorPanel 동작만 격리한 자체 helper를 만든다.

비공개 API 의존성 때문에 Mac App Store보다 Developer ID 서명 및 Apple 공증을 거친 직접 배포를 기본 경로로 삼는다. macOS 업데이트마다 회귀 테스트가 필요하다.

## 2. 제품 범위

첫 버전의 권장 범위는 다음과 같다.

- Apple Silicon MacBook
- macOS 15 이상
- 내장 디스플레이 수동 회전
- 0°, 90°, 180°, 270° 선택
- 다음 방향으로 회전하는 전역 단축키
- 로그인 시 자동 실행
- 잠자기에서 깨어난 뒤 마지막 방향 복원
- 변경 확인 실패 또는 시간 초과 시 원래 방향 자동 복구
- Developer ID 직접 배포

자이로 센서를 이용한 자동 회전은 공식 센서 API의 가용성과 안정성을 별도로 검증한 뒤 후속 범위로 다룬다.

## 3. 권장 구조

```text
SwiftUI 메뉴 막대 앱
        |
        +-- Display Discovery
        |     +-- CGGetActiveDisplayList
        |     +-- CGDisplayIsBuiltin
        |     +-- CGDisplayRotation
        |
        +-- Rotation Engine
        |     +-- 격리된 비공개 API helper
        |     +-- 적용 결과 확인
        |
        +-- Recovery Manager
        |     +-- 변경 전 상태 저장
        |     +-- 확인 타이머
        |     +-- 실패/크래시 복구
        |
        +-- 단축키, 로그인 실행, 설정 저장
```

## 4. 단계별 계획

### 0단계: 기술 PoC (1일)

목표는 제품 UI를 만들기 전에 대상 Mac에서 회전 기능의 실제 작동 여부와 위험 요소를 확인하는 것이다.

작업:

- 활성 디스플레이와 내장 디스플레이 식별
- 현재 각도, 해상도, 스케일, 주사율 기록
- 90° 회전 후 원래 각도로 자동 복구
- 180°와 270° 반복 검증
- 회전 전후 모드와 디스플레이 식별자 비교
- 관리자 암호, 화면 기록, 손쉬운 사용 권한 필요 여부 확인
- 결과를 `docs/poc-results.md`에 기록

안전 원칙:

- 실제 회전은 사용자가 명시적으로 `rotate-test`를 실행할 때만 수행한다.
- 원래 각도를 실행 전에 파일에 기록한다.
- 별도 복구 프로세스를 먼저 시작한다.
- 기본 15초 후 자동 원복한다.
- 성공 여부와 무관하게 종료 시 원복을 다시 시도한다.
- `--keep` 같은 자동 원복 해제 옵션은 PoC에 제공하지 않는다.

완료 조건:

- 내장 디스플레이를 외장 디스플레이와 구별한다.
- 0°, 90°, 180°, 270° 전환 결과를 읽어서 확인한다.
- 원래 해상도, 스케일 및 주사율이 복구된다.
- 로그아웃이나 재부팅 없이 원래 상태로 돌아온다.
- 필요한 권한과 알려진 실패 조건이 문서화된다.

### 1단계: Rotation Core (1~2일)

- 회전 엔진을 UI와 분리된 모듈로 구성
- 디스플레이 열거와 내장 화면 판별
- 현재 방향 조회와 방향 변경
- 오류 코드 정규화
- 변경 전후 구성 저장
- 15초 확인 및 자동 원복
- 단위 테스트와 CLI 진단 도구 제공

### 2단계: 메뉴 막대 MVP (2일)

- SwiftUI `MenuBarExtra`
- 네 방향 선택과 현재 방향 표시
- 다음 방향 회전 단축키
- 작업 중 중복 실행 방지
- 성공/실패 알림
- 로그인 시 실행

### 3단계: 안정성 보강 (2~3일)

- 잠자기 및 깨우기 대응
- 디스플레이 연결 구성 변경 감지
- 외장 모니터 연결 후에도 내장 화면 재식별
- 회전 후 유효한 디스플레이 모드 선택
- 앱 비정상 종료 후 복구
- VoiceOver 접근성
- 진단 로그와 긴급 원복 기능

### 4단계: 호환성 시험 (2~4일)

시험 범위:

- 확보 가능한 M1~M5 MacBook
- macOS 15와 macOS 26
- MacBook Air와 MacBook Pro
- 외장 모니터 없음, 확장, 미러링
- 잠자기, 덮개 닫기, 재부팅, 사용자 전환
- 각도별 해상도와 포인터 좌표
- 전체 화면 앱과 화면 녹화 중 회전

### 5단계: 직접 배포 (1~2일)

- Developer ID 서명
- Hardened Runtime
- Apple 공증
- DMG 또는 ZIP 패키징
- Sparkle 자동 업데이트
- 오픈소스 라이선스 고지
- 지원 macOS와 비공개 API 의존성 명시

## 5. 예상 일정

- 0단계 PoC: 1일
- 기능 MVP: PoC 성공 후 약 1주
- 배포 가능한 안정화 버전: 약 2주

0단계에서 내장 화면 회전이 실패하면 전체 앱 구현에 들어가지 않고 macOS 버전별 대체 엔진, 가상 디스플레이 또는 제한된 시스템 설정 자동화를 검토한다.

## 6. 현재 검증 환경

- MacBook Pro (Mac17,2)
- Apple M5
- macOS 26.2 (25C56)
- arm64
- Xcode 26.6
- Swift 6.3.3
